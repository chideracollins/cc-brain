# Project Pages

This folder contains pages documenting each project with a consistent structure.

Every page answers **What problem → What I built → Measurable result → Evidence link**.
If a claim has no repo artifact behind it, it doesn't ship.

## Template (`project-pages/<project>.md`)

```markdown
# <Project>
## Problem          — who had it, why it mattered (not "I built a todo app")
## What I built     — 2-4 bullets, architecture/stacks decisions + the WORST decision, why
## Measurable result— numbers: load time, throughput, users, tests passing; or "no metric yet — planned"
## Evidence         — repo link, test output, screenshot, deploy URL (each claim's artifact)
## What I'd change  — hindsight + what backs that judgment
```
